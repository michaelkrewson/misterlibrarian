🇿🇦 South Africa UPDATE 2026-09-09: found a genuinely keyless, no-auth REST API after all — custom.resbank.co.za/SarbWebApi (its OpenAPI spec declares no security scheme at all, confirmed live). But its 4 curated "Money and Banking" snapshot-graph endpoints turned out to be interest rates and CPI, not money supply; the real money-supply codes (MON0100P/MON0200P/MON0300P) were found by guessing off SARB's own MON-prefix pattern — and every one of them is a 12-month %-CHANGE series (M1/M2/M3 y/y), not a level. This board's schema needs LEVELS (native-currency amounts, summed into the totals row and the scarcity chart) — a % change doesn't fit that shape, so nothing was added despite having real, live, keyless data in hand. SARB's own classic series use a DIFFERENT "KBP"-prefixed code scheme (confirmed via its Online Statistical Query tool's own instructions) for level data, and no KBP code for M0/M1/M2/M3 levels could be found within reasonable effort — the interactive query tool itself would need to be driven to reveal one. A real candidate for a future dated follow-up, not a dead end. — — — —
🇮🇱 Israel The Bank of Israel runs a real, modern, keyless SDMX 2.1 API at edge.boi.gov.il — confirmed live, and its dataflow list even names the exact one wanted ("MAG" = "Monetay Aggregates", their own typo). But its data response encodes each series as a compact dimension-index key (e.g. "3:0:1:2:1:1:0:2") rather than a named code — decoding which key is M0/M1/M2/M3 needs the dataflow's full structure/dimension map fetched and cross-referenced, a genuinely deeper task than every other provider here (all of which return self-describing codes or labels directly in the data response). A real candidate for a future dated follow-up, not a dead end — the API and the right dataflow are both confirmed to exist. — — — —

Euro area monetary base (M0) is the one figure on this whole board that is hand-curated rather than live-queried. The Eurosystem calls it "Base money" (banknotes in circulation plus bank reserves at the ECB — the same idea as the Fed's monetary base) and states it in plain English every week in its own Consolidated Financial Statement press release — but the underlying series lives in a different ECB dataset (Internal Liquidity Management, the Eurosystem's own weekly financial statement) from the one used for M1/M2/M3 here (Balance Sheet Items), and a real, substantial attempt at a live keyless query against it — the exact item code plus roughly 155 real dimension-value combinations tried against the ECB's own API — found no working query. So this figure is read by hand from that weekly release (2026-09-04) and refreshed periodically rather than every build, the same posture this board already takes with gold reserves — its DOLLAR value still recomputes from today's live exchange rate like every other cell here, only the underlying euro figure itself is periodic. The totals row above therefore blends one periodic figure into an otherwise-live row.
