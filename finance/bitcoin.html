How these numbers are made

Three different kinds of number sit on this page, and they are not equally true. Rather than set them all in the same type and let you assume, here is which is which.

  • Computed, and exact. Everything about supply and halvings. Bitcoin's issuance is a published rule — 50 coins a block, halved every 210,000 blocks — so the number of coins in existence is not an estimate anyone has to make. It is that schedule added up in whole satoshis from the block height above, and the working is set out here.
  • Polled, and live. Price, block height, the mempool and the fee estimates are refreshed from mempool.space every minute while this page is open; difficulty and hash rate every five, because they cannot move faster than that. If those requests fail the page keeps the last good reading and says so beside the dot at the top.
  • Snapshots, taken hourly. The all-time high, both charts, the chain's size and its all-time totals. Lightning is the exception worth knowing about: its upstream statistics are rebuilt on someone else's schedule, so that panel carries its own date.

The clocks — time since the last block, and the two countdowns — tick without asking anything, because they are arithmetic on a timestamp. The halving countdown assumes Bitcoin's ten-minute target, so it is an estimate that jumps a little each time a block actually lands.

Some things a board like this usually shows are missing on purpose: the size of the UTXO set, accumulated chain work, the breakdown of output types, coinjoin activity, how much bitcoin sits on company balance sheets. Those need a full node with an address index, or a list somebody keeps by hand. A number invented to fill a gap is worse than the gap.
